# Change control

Every pinned external artefact, with the exact reference in use and the date it
was captured. A digest without a capture date is a number nobody can audit.

## How to record an image

The inspect command returns a **repository digest**, which looks like:

```
postgres@sha256:1f4b2c...e9
```

That is the repository plus the digest, with no tag. What goes in `.env` is the
**tag and the digest together**, so a human can read which version it is and
Docker can verify exactly which bytes:

```
POSTGRES_IMAGE=postgres:16@sha256:f1c3376c26f2609ab9f29f71f824103fe2fcd8ee0346485cb6122a4f93df6f94
                        ^^^^^^^^ ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
                        readable  enforced
```

Capture both with:

```bash
docker pull postgres:16
docker image inspect --format '{{index .RepoDigests 0}}' postgres:16

docker pull python:3.12-slim
docker image inspect --format '{{index .RepoDigests 0}}' python:3.12-slim
```

Take the part after `@` and paste it after your tag.

## Dependency lock files

`requirements.txt` and `requirements-dev.txt` are generated by `make lock` and
committed. They carry hashes, and the Dockerfile installs with
`--require-hashes` and no fallback.

`make lock` compiles **inside the runtime image**, not on macOS, so the
resolution matches the platform that will run it. A lock file compiled on Apple
Silicon can select different wheels from the ones a Linux container needs.

| ---------------------- | -------------- | ---------------- |
| `requirements.txt`     | `make lock`    | `TBD`            |
| `requirements-dev.txt` | `make lock`    | `TBD`            |

## What is deliberately not pinned

GitHub Actions are referenced by major tag (`actions/checkout@v4`) rather than
by commit SHA. Pinning to a SHA is stricter and is what a production repository
should do; it is recorded here as a known gap rather than left unstated.
